# 万界武库 v1.6.8

整理剧情、管理能力成果与档案的 SillyTavern 扩展。原文状态栏记录当前状态，长期子表按对象接续更新，重要事件分别留档。

## 安装与更新

在酒馆扩展管理中使用仓库地址 https://github.com/feiluoze/wanjie-wuku 安装；已安装的玩家点击更新并刷新，面板应显示 **1.6.8**。更新前保存当前聊天；若有尚未安全保存的数据，先导出档案。

玩家更新直接读取安装分支源码，不需要 GitHub Release 或附件。

## 1.6.8 更新

- AI 整理结果的弹窗顶部新增“本次同步摘要”：分别显示主状态栏、各已启用子表的新建、更新、基础记录和待补全数量。摘要只按本批候选统计，不增加模型调用，也不改变保存和校验。
- 子表区和长期档案库增加“待补全”入口，可只看明细仍为空的基础记录；卡片继续显示“详情待补充”，补全后自动移出。
- 自动更新区增加“撤销上次：自动整理 / 整理剧情”入口，沿用原有单步撤销和防护，不覆盖后续档案。
- AI 任务浮层显示本次请求的输入字符数和估算 tokens，发送前后都能看到；只读展示，不增加调用。
- 同名多档不再按更新时间猜对象：未通过项里会列出可选目标，选定后用原候选本地重校。
- 新增只读“数据健康”检查：同名多条子表、未知分类、旧通用同名和待补全记录；只提供查看入口，不自动合并、覆盖或删除。
- “其他设置与管理”增加简洁界面开关：隐藏高级与支持面板，保留状态、子表和主要操作；只记在本机浏览器，不删除数据。

详见[同步摘要与待补全](docs/同步摘要与待补全-1.6.8.md)。

## 1.6.7 更新

- 修复手机主界面内容被截断、无法向下滑动的问题；正文与侧栏由外层统一纵向滚动，刷新时保留滚动位置，桌面仍使用原有布局。

- 悬浮入口与边缘收起标签显示红色待处理数量，提醒确认整理候选、行动结果及处理角色同步。打开面板不会清除提醒，处理完成后自动消失；切换聊天按当前档案重新计算。

- 修复基础建档把整段引文填进等级等属性的问题；缺失属性保持空白，卡片显示详情待补充。旧档中可明确识别的自动填入名单不再当属性展示或发送给AI；原始引文和历史保留在来源详情。

- 修正整合：错列名等问题只隔离受影响字段，合法内容仍可保存；同名多档按明确ID或唯一身份定位，不按更新时间猜对象。太始天未完成的来源继续待重查，普通武库不恢复逐层报告门槛。

- 初始化和每次更新都把主状态栏与所有已启用子表一起交给 AI 核对：该建档就建档，有变化就更新，无变化保留。主表已有概括、子表为空、缺详细属性或本轮没有数值增长，都不再成为跳过子表的理由。
- 子表允许“基础记录”：只确认名称与原文依据即可先建档，详细列留空；后续正文补充时沿同一对象更新，不再要求首次就填满身份列、明细字段或 archiveId。
- 移除普通武库的逐层完整性报告与保存门槛；缺报告、报告数量不一致或报告 uncertain 不再阻止有效候选保存。太始天专题仍保留其分工报告。
- 保留必要底线：不编造原文没有的内容，不重复建档，不覆盖未变化数据；关闭/收拢的旧分类仍只接续旧档。目录、详情、历史与旧档案不自动迁移或删除。

详见[子表同步与限制清理](docs/子表同步与限制清理-1.6.7.md)。

## 1.6.5 更新

## 1.6.4 更新

- 补查旧楼层时，已被同一对象较新正文值取代的状态快照可自动忽略；程序按字段历史核对来源，避免旧进度、旧库存反复要求手动处理。独立奖励、事件与漏记成果继续核对，来源不明或正文已改写时仍保留待查。

- 本次修复：整理正文时按字段保留冲突，独立且有依据的内容仍可形成候选；冲突字段不覆盖旧值，读取进度继续保留待核对。逐层结果显示具体未决原因。旧楼层重查、正常消耗与无依据的数值回退分别处理，不按最大值或自行累加修正账目。

- AI连接与方案新增“管理／导入预设”：可导入酒馆补全预设JSON，也可在酒馆提供接口时复制已安装预设；逐块勾选、上移下移、编辑角色和全文，保存为独立快照。
- 整理与自动更新、拟定、终端、初始化和其他核对等任务分别选择预设，默认关闭；关闭后恢复武库原提示。JSON格式、来源归属、防重复与账目校验继续执行，导入不会修改主聊天预设或玩家档案。
- 支持预设导出与删除；预设保存到当前酒馆账户，不随聊天档案导出，不导入API地址、Key或采样参数。常用名字及变量宏在单次请求内解析；暂不支持的宏会在发送前报错，不调用宿主宏执行器。
- 提示块组装同时接入独立API与沿用酒馆连接。参考故事神谕的块选择、独立快照与按任务启用思路，代码独立实现，没有内置第三方破限文本。详见[自定义预设说明](docs/自定义提示词预设.md)。

## 使用

1. 接入金手指，继续正常剧情；在主界面执行“AI 整理剧情”。
2. 核对候选中的原对象、字段、状态与来源，确认后保存。自动保存沿用玩家已有设置。
3. “现在”查看当前状态与长期档案；“行动”用一句话让 AI 按词条给出方案；“背包”查看已经到手的能力、物品与消耗品；“记录”查看每次扣付、获得与承接。
4. 余额通过“核对资源余额”或已有角色 MVU 绑定维护，整理档案不会再次扣款、发奖或自动补算收益。
5. 选中左侧词条后，词条名旁的“⋯”可查看规则、暂停/恢复接入或删除当前词条；删除需再次确认，并可先导出备份。
6. 初始化与每次整理会同时核对主状态栏和已启用子表；新对象可先建基础记录，明细留空，后续补充同一条。

模型格式失败会保留候选。主动“AI 修复未通过项”会消耗所配接口额度，修复后仍需核对。

## 数据与兼容

旧档案和历史保留，不自动拆分、清理或迁移；同名旧通用档案不会自动转换为子表。只有当前原文指纹与声明匹配时启用内置适配。状态栏主表、长期明细和专属资源账本各有职责；不引入外部 SQL 服务。

未声明子表的其他词条和太始天继续使用原有流程。漫漫长路表格直接读取既有八部档案，存储与保存流程不变。语义判断仍依赖模型与玩家核对，不能保证所有改名和同义描述都能自动去重。
