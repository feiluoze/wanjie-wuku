# 万界武库 v1.6.4

整理剧情、管理能力成果与档案的 SillyTavern 扩展。原文状态栏记录当前状态，长期子表按对象接续更新，重要事件分别留档。

## 安装与更新

在酒馆扩展管理中使用仓库地址 https://github.com/feiluoze/wanjie-wuku 安装；已安装的玩家点击更新并刷新，面板应显示 **1.6.4**。更新前保存当前聊天；若有尚未安全保存的数据，先导出档案。

玩家更新直接读取安装分支源码，不需要 GitHub Release 或附件。

## 1.6.4 更新

- 补查旧楼层时，已被同一对象较新正文值取代的状态快照可自动忽略；程序按字段历史核对来源，避免旧进度、旧库存反复要求手动处理。独立奖励、事件与漏记成果继续核对，来源不明或正文已改写时仍保留待查。

- 本次修复：整理正文时按字段保留冲突，独立且有依据的内容仍可形成候选；冲突字段不覆盖旧值，读取进度继续保留待核对。逐层结果显示具体未决原因。旧楼层重查、正常消耗与无依据的数值回退分别处理，不按最大值或自行累加修正账目。

- AI连接与方案新增“管理／导入预设”：可导入酒馆补全预设JSON，也可在酒馆提供接口时复制已安装预设；逐块勾选、上移下移、编辑角色和全文，保存为独立快照。
- 整理与自动更新、拟定、终端、初始化和其他核对等任务分别选择预设，默认关闭；关闭后恢复武库原提示。JSON格式、来源归属、防重复与账目校验继续执行，导入不会修改主聊天预设或玩家档案。
- 支持预设导出与删除；预设保存到当前酒馆账户，不随聊天档案导出，不导入API地址、Key或采样参数。常用名字及变量宏在单次请求内解析；暂不支持的宏会在发送前报错，不调用宿主宏执行器。
- 提示块组装同时接入独立API与沿用酒馆连接。参考故事神谕的块选择、独立快照与按任务启用思路，代码独立实现，没有内置第三方破限文本。详见[自定义预设说明](docs/自定义提示词预设.md)。

## 1.6.3 更新

- 修复正式结算标注“已入账／待提取”“已归档”仍被归属校验拦截的问题；可用同层回执关联正文成果，不要求模型把对象名称反复写进每句引文。待提取不视为已交付，不改资源或进展状态。编号回执逐项区分归属，防止串到上一词条。
- 通用归属修复：不再凭展示标题的前缀判断属于哪个词条；分行结算沿用所属标题，混合多个词条的引用保留待核对，已有档案ID也不能绕过来源归属。主状态栏与独立对象分别定位，子表漏填operation不能用分类标题冒充新对象。没有要求普通叙事每句都写词条名。
- 归属证据集中到共用流程，玩法特有的必要联系由规则绑定的声明提供；不修改原世界书、余额或已有档案。详见[通用归属校验说明](docs/通用归属校验.md)。

- 格式修复先尝试本地恢复已声明键名漏引号等确定性语法错误，不能恢复时才按现有操作请求AI；原候选、玩法说明和原有进展不会因识别失败被误当成新增内容。截断、未知键、缺少值或含糊损坏仍保留待核对，不补写事实。
- 收紧填表预设：主状态栏与长期子表操作范围分开，输出字段与实际协议对齐，系统提示不再重复携带同一段长规则；保留事实、归属与防重复校验。
- 挂机的主状态栏不再误套首次新增成果的标题限制；探索记录可凭原文同句的明确地点与征伐之影证明归属，不因展示标题概括而卡住，也不放行其他能力的成果。

本轮取舍见[填表协议与格式修复](docs/填表协议-可靠性修复.md)。

- 修复原文状态栏误带insert/update后被子表校验拦截、AI修复仍反复失败的问题；兼容标记按原状态栏身份接续，重复整理不新增主记录。长期子表的操作限制与防重复规则保持。

- 新接入词条时，可以选择需要长期记录的框架：能力、重要资产、成员、区域建设、知识、长期线索、持续安排。已有词条也能在管理页修改；可以全部关闭。原状态栏、余额账本照常使用，关闭框架不删除旧档案。
- 补齐后续批次的必要子表，并完成内置词条审查：47个词条保留59类默认子表，另外3个已审词条沿用原状态栏。优先复用已有专属表，同一事实不重复铺表，日常训练、临时过程和普通收支不单独长期记录。
- 自动更新遇到网络故障、限流或明确的服务暂不可用时，单次请求最多尝试3次，等待8秒、20秒；已设置的备用连接也计入总次数。可能增加API费用。取消、切换聊天或剧情变化会停止后续请求，成功响应只进入一次正常校验与保存。
- 修复HTTP 200内返回“Service Unavailable”却被视为不可重试的问题。格式不完整、校验不通过、额度不足、鉴权失败不在自动重试范围；沿用酒馆连接超时且生成可能仍在运行时，不重复启动同一连接。
- 左侧“我的金手指”选中词条后显示“⋯”菜单，集中查看规则、暂停/恢复接入和删除当前词条；删除仍在原确认弹窗中执行，并保留先导出备份的入口。主区域“更多操作”继续放整理、补录和纠错，不再重复删除入口。
- 保留旧档案、详情和历史，不自动迁移或删除。没有为子表新增货币、数值规则或奖励，也不改变世界书正文。

详见[通用记录框架说明](docs/通用记录框架-玩家选择.md)、[全部剩余词条审查](docs/长期子表-剩余词条审查与分批制作.md)。功能分类目前用于框架推荐，完整分类筛选入口尚未接入。

## 使用

1. 接入金手指，继续正常剧情；在主界面执行“AI 整理剧情”。
2. 核对候选中的原对象、字段、状态与来源，确认后保存。自动保存沿用玩家已有设置。
3. “现在”查看当前状态与长期档案；“行动”用一句话让 AI 按词条给出方案；“背包”查看已经到手的能力、物品与消耗品；“记录”查看每次扣付、获得与承接。
4. 余额通过“核对资源余额”或已有角色 MVU 绑定维护，整理档案不会再次扣款、发奖或自动补算收益。
5. 选中左侧词条后，词条名旁的“⋯”可查看规则、暂停/恢复接入或删除当前词条；删除需再次确认，并可先导出备份。

模型格式失败会保留候选。主动“AI 修复未通过项”会消耗所配接口额度，修复后仍需核对。

## 数据与兼容

旧档案和历史保留，不自动拆分、清理或迁移；同名旧通用档案不会自动转换为子表。只有当前原文指纹与声明匹配时启用内置适配。状态栏主表、长期明细和专属资源账本各有职责；不引入外部 SQL 服务。

未声明子表的其他词条和太始天继续使用原有流程。漫漫长路表格直接读取既有八部档案，存储与保存流程不变。语义判断仍依赖模型与玩家核对，不能保证所有改名和同义描述都能自动去重。
