# 万界武库 v1.6.0

整理剧情、管理能力成果与档案的 SillyTavern 扩展。原文状态栏记录当前状态，长期子表按对象接续更新，重要事件分别留档。

## 安装与更新

在酒馆扩展管理中使用仓库地址 https://github.com/feiluoze/wanjie-wuku 安装；已安装的玩家点击更新并刷新，面板应显示 **1.6.0**。更新前保存当前聊天；若有尚未安全保存的数据，先导出档案。

玩家更新直接读取安装分支源码，不需要 GitHub Release 或附件。

## 1.6.0 更新

- 首批 **9 个词条、28 类长期子表**：万界网购、升变之印、天人骨血、熟练度状态栏、先祖投资人、道途、自我束缚、心渊、败家生财。沿用 21 类现有分类，补齐 7 类明细；每类都有保留与更新条件。
- 同一技能、形态、资产、契约更新原对象；独立订单、投资、支出各自留档。新增、更新、状态变化明确区分，歧义不会自动猜测合并。
- 首批词条逐层整理使用隔离的批次工作副本，后层能看到前层已校验候选。候选统一确认后写入，取消或失败不提前修改正式档案。
- 首页增加“长期档案”入口，可按子表搜索、筛选状态、打开详情和手动纠错。没有记录的分类也能直接打开。
- 事件子表默认不自动注入正文，仍可查询并由玩家选为记忆；普通练习、恢复和一次性细节不要求逐条入表。保存诊断区分操作次数、独立对象和无变化项。
- 合并五处旧专用余额列的保护：故事点、恋爱点数、抽奖次数、势差值、升变点只读引用现有资源账本，收支依据仍可维护。

详见[长期子表使用说明](docs/长期子表-1.6.md)。

## 使用

1. 接入金手指，继续正常剧情；在主界面执行“AI 整理剧情”。
2. 核对候选中的原对象、字段、状态与来源，确认后保存。自动保存沿用玩家已有设置。
3. “当前状态”查看原文状态栏，“长期档案”查看独立对象，“查看档案”搜索全部内容。
4. 余额通过“核对资源余额”或已有角色 MVU 绑定维护，整理档案不会再次扣款、发奖或自动补算收益。

模型格式失败会保留候选。主动“AI 修复未通过项”会消耗所配接口额度，修复后仍需核对。

## 数据与兼容

旧档案和历史保留，不自动拆分、清理或迁移；同名旧通用档案不会自动转换为子表。只有当前原文指纹与声明匹配时启用内置适配。状态栏主表、长期明细和专属资源账本各有职责；不引入外部 SQL 服务。

未声明子表的其他词条、漫漫长路和太始天继续使用原有流程。语义判断仍依赖模型与玩家核对，不能保证所有改名和同义描述都能自动去重。

## 验证与维护

单元回归、逐层控制器测试与桌面/手机模拟宿主检查覆盖新增链路；运行 `npm test`，浏览器测试使用 `tests/archive-tables-browser.mjs`。真实酒馆、多插件组合与真实模型返回仍需现场验证。

维护者采用扩展仓库更新流程：检查与测试 → 同步版本和 README → GitHub 插件提交源码 → 核对远程内容与 Commit SHA。默认不创建 Release、附件或 ZIP，也不提交临时打包脚本和玩家数据。详细约定见 [AGENTS.md](AGENTS.md)。
