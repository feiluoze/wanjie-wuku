# 1.6 长期子表

原文状态栏是当前总览，子表展开未来仍要使用、持续变化或需要追溯的重要对象。它们使用同一套聊天档案存储，不是外部数据库，也不另外复制资源余额。

| 词条 | 首批分类 |
| --- | --- |
| 万界网购 | 订单与交付、有效交易委托、暂存与重要资产、收藏与关注目标 |
| 升变之印 | 升变形态、重要分支、唯一任务槽、实际投入与收支依据 |
| 天人骨血 | 永久生命特征、统合生命结构 |
| 熟练度状态栏 | 技能、重要训练 |
| 先祖投资人 | 独立投资、投资史线、当前家系、实际继承、待兑现事项 |
| 道途 | 道途契约、重要践行、关键节点 |
| 自我束缚 | 束缚契约、重要兑付 |
| 心渊 | 永久渊痕、重要遗藏与钥痕、探索与临时构筑 |
| 败家生财 | 重要实际支出、当前财富、消费安排 |

共 28 类，复用 21 类既有分类，补齐天人骨血 2 类、自我束缚 2 类、心渊 3 类。上表为概念名称，界面沿用已存在的完整分类名。模板只声明可以保留什么，不会自动给玩家生成能力、资产或空记录。

## 怎么用

照常整理剧情，不必手工维护表号或行号。首页“长期档案”会显示这个词条的分类；点击“打开子表”或“查看 N 项”，即可搜索、按状态筛选、打开记录查看来源，或在详情中纠错。未确认栏目留空。结束的记录仍可按状态查询，不会自动删除。

原文的当前总览继续维护；子表保存独立明细，避免往总览描述里反复塞入整份清单。点数、能量、次数与现有账本共用，档案写有付款或交付不代表插件再次执行扣款。

## 新增、更新与状态变化

- `insert`：确实出现了新的独立对象或事件；本地分配稳定档案 ID。不能对已有对象重复新增。
- `update`：沿用原 `archiveId`，只提交变化的列，省略的列保持。名称/旧名恰好唯一时也可定位；多匹配拒绝猜测。
- `transition`：同一对象出现明确状态变化，例如计划开始执行、任务确已结束；不表示再次结算收益。

例如“耐火鳞甲取得 → 后来深化”接续同一记录。“首次买剑 → 第二次又买剑”是两笔独立订单，名称须区别具体交易；商品相同不等于订单相同。阶段标题改变仍应沿用 ID，不能借改名重复建档。唯一任务槽、统一家系只有一条主记录，不能新增平行副本。

新请求的子表输出声明上述操作；旧缓存候选与旧合法格式继续兼容。模型提供新名称、又不指明原对象时，程序无法可靠识别所有语义别名，仍可能需要核对；不会用模糊相似度擅自合并两件不同事物。

## 保留的度

优先保留：永久能力和特征、重要资产及归属、后续仍约束行动的契约、未完任务和真实重要结算。普通恢复、每次练习、路过人物、未选方案、一般节点经过不逐条扩成长期明细。

`entity` 是持续对象，更新当前状态；`singleton` 是唯一当前记录；`event` 是重要独立事件，用于追溯。事件表默认不进入自动正文记忆的概况或关键词匹配；玩家仍可选择“带入正文”。其他档案和原文总览按已有记忆预算处理，不扩大字符预算。

心渊的临时构筑和永久渊痕分别维护；归返后保留真实取得的永久成果。只有正文明确结束，才把当前探索或临时记录标为结束，不从“本轮没提及”推断失效。自我束缚保留宣告时已成立的条件，不新增原文没有的偿还义务或违约惩罚。

## 多楼层与保存

首批词条的普通逐层整理使用本批工作副本。每层经过字段、身份、来源和报告校验后，才用于下一层上下文；失败、报告缺失/矛盾或未完成核对的楼层不会污染工作副本。新增对象的临时 ID 不发给模型、不提前写入档案。

最终仍使用原有候选确认和 ChatStore 事务，保持聊天/版本/正文变化检查。取消不保存；只接受部分候选时，未接受楼层不会假装处理完成。原始失败候选与既有恢复入口继续保留，不默认追加付费重试。

运行日志的保存结果分别列出 `operations`（实际写入次数）、`objects`（独立对象数）、`created`、`updated`、`ended` 和 `unchanged`。连续两层更新同一对象可能是两次操作、一个对象，不是新增两个成果。

## 旧档案与边界

不自动重写、迁移、删除旧通用记录，也不自动合并已有重复项；同名旧通用档案存在时要求先核对。历史余额快照的原值保留，当前显示与记忆只读现有资源账本。原文改动后不套用旧的内置声明；自定义适配不凭名称冒用内置字段。

子表仍受现有单词条档案及历史上限保护。保留条件是模型提取规范，不是把所有自然语言细节转成可靠数据库约束；复杂身份与真实模型输出仍须玩家核对。此版本未实现旧数据批量迁移、语义自动合并或所有词条全量子表适配。
