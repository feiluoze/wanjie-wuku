# 填表协议与格式修复（1.6.3）

## 对照的数据库源码

本轮静态读取[数据库 naiv1.2.9 对应提交](https://github.com/AlbusKen/shujuku/blob/85eaa78ab6908adc84a2ef5c5278f25e8d296317/index.js)，Git blob为7cdecc5297060e66a81d74f7f855a52a307a4e19，SHA256为afc83e77a113ec4a37c422c0dc4dfd1c7b7f52bdc8237f5e8f7c6ea5d408ee48。只读取源码，没有运行上游脚本或把源码打进插件。

值得借鉴的是：任务、背景与当前表格分区；表和列必须来自声明；更新定位原行；输出模式与解析器配套；解析/提交错误分开诊断，并限制重试次数。源码包含严格JSON、工具和正文tableEdit多种通道；默认strictJsonTableFillEnabled与tableFillNativeToolEnabled为false，不能把支持能力误写成默认启用。

武库采用这些数据契约原则，继续使用既有JSON候选、来源校验和确认保存。没有引入SQL、脚本执行、delete操作、输出思维过程或默认无限重试，也没有复制其角色扮演确认语句。模型真实成功率仍需实际接口验证。

## 普通填表

responseContract.outputs规定本次根字段；operationScope明确哪些recordId属于可写长期子表，其余记录不填写operation。recordSchemas提供真实列名和文字字段。原文状态栏按原身份接续，不按楼层创建副本。

系统提示引用输入中的权威规则，不把originalStatusbar.rules与longTermTables.rules再完整复制一遍。三个无正文样本（挂机、绝对生产力、源堡）的系统提示分别减少441字符；输入中完整规则仍保留。此测量不是token预算或模型成功率承诺。

## 语法修复

只在对象键位置、字段已被捕获的schema声明时，修复漏写键名闭引号的语法错误；不改字符串、数值、引文、名称、ID、状态与归属。输入限120000字符、嵌套深度64、最多8处键名引号修复；未知键、重复键、缺值和不闭合容器不采用这种恢复。

普通整理不因解析失败自行追加模型调用。玩家点击现有修复按钮时先执行本地恢复；无法确定才走已有AI修复操作。提示与合并校验共用一个输出边界，原回复已有且原协议允许的guide/terminalResults/creationResults才可保留；不能为通过校验加新字段或编造内容。可确定恢复的原候选必须逐项保真，实际字段、来源和玩法证据仍执行原校验。

若结构仍无法可靠恢复，旧候选继续保留，不自动推进楼层。先修语法，再核对事实；语法正确不等于内容正确。

## 挂机归属

原文状态栏走现有主表校验，不再要求主表标题符合新增独立成果的命名规则。独立探索记录若采用概括标题，必须在连续引文同一句中出现其实际location与原规则角色“征伐之影”；此依据只用于已适配的挂机探索表。其他地点、其他能力、普通学习和借用设施不会因此取得归属。

## 验证边界

新增测试覆盖语法恢复、未知/重复键拒绝、原玩法说明和进展保留、候选篡改拒绝、取消前不落盘、挂机正反归属和预设字段范围。实际私有失败候选仅在本地回放，未放入仓库。模拟浏览器不代表真实酒馆验收；没有修改玩家聊天、变量或档案。
