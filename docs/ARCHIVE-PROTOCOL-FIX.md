# 通用档案整理修复记录

本轮修改的是源代码中的通用整理链路，适用于万界武库、太始天和漫漫长路，不按某位玩家的人名、剧情、时间或能力结果匹配。没有修改或打包玩家正文。本轮修复已并入1.3.6待发布源码与重新生成的安装包；原1.4.0旧ZIP不含本轮修复。尚未安装、推送或发布。

## 已修改的行为

- 模型输入将叙事、正式结算、状态快照分开。后续机会独立标明为未选择事项；通用的 `*-settle`、`*-status`、`*-state` 协议使用同一路径。剧情规划标签在发送给整理模型前过滤。旧版来源读取函数、哈希和已保存锚点保持原协议，不因新过滤方式使旧档案失效。
- 引文仅出现在被排除的规划或未选择机会中时拒绝候选，不能借原始来源文本仍保留这些内容绕过事实分区。概括性引文不以逐字匹配强行判错；程序不声称能自动判断所有概括是否正确。
- 多楼层引用优先按唯一原文定位。缺失或错误的楼层无法唯一定位时拒绝候选，不再默认归到最后一层。合法明确楼层仍允许概括性引文；单一来源不存在跨楼层歧义，可以定位该唯一来源。
- 通用字段与专用字段分别按声明校验；确定的中文显示标签可转换成字段 ID。专用字段误放通用 fields 时按当前 recordId 转入 details。只提供专用字段时，用原值生成展示简介，不推算或改写游戏结果。未知字段与别名冲突明确报错。
- 当前词条已有专用适配时，自动/正文整理必须使用已声明的 recordId，不能用通用技能、关系档案绕过专用记录范围。未适配词条仍可走通用档案；玩家口述补录保留原入口。
- 所有模块统一检查明确的其他词条所有者、协议标题和词条名称前缀。协作不等于转移所有权。没有确定规则支持的语义归属仍由模型核对，程序不凭关键词猜测游戏结果。
- 每层要求单独返回核对状态和条目数量。漏报、重复报告、数量不一致或 uncertain 不推进该层进度。有效候选仍可保存，待重查楼层不被一次确认吞掉。前端有默认折叠的逐层结果。
- 部分自动整理遇到未完成楼层后停止当前批次循环，不自动重试付费请求；玩家可继续操作、手动补录或重查。
- 单独的状态快照不能把已有明确成果清成空值、“无”“暂无”“未知”等。明确叙事更正及玩家手动更正保留；数值余额不由此流程重新结算。
- 默认校验日志记录数量、楼层及原因码，去除候选名称、引用原文和其他所有者名称。详细问题仍在本地预览展示；显式开启详细日志仍可能包含原文，不应外发。既有历史日志不自动改写。
- 太始天高级工作流保留各专职的逐层报告，合并后再校验。不增加请求次数，不自动升级模型或重试。

## 自动化证据

- Node 全量回归：921 项，908 通过，0 失败，13 项因缺少外部样本跳过。
- 新增通用协议测试使用自编数据，覆盖不同协议、多楼层来源、所有已声明适配器字段标签、跨词条所有者、独立历史记录保留、空结果确认、快照清空防护、自动停止及日志隐私。
- 更新旧模拟模型回复，明确返回新的逐层协议；保留并反向验证“无来源默认最新层”旧行为已被移除。
- 模拟宿主浏览器：1440、390、320 像素，通过分区输入、逐层结果展开、有效条目保存及旧楼层继续可重查的检查；无外部请求、无浏览器脚本错误。
- 主要修改模块通过 Node 语法检查。

## 验证边界

模拟宿主不是用户的真实 SillyTavern。尚未在真实安装环境导入，也未调用真实模型验证其逐层提取完整率。模型仍可能语义判断错误；这些改动使结构错误和未完成核对可见、可重查，不声称自动证明每一项剧情语义或绝不漏项。

新模型协议不完整时会保留进度并提示，不静默兼容成“全部成功”。这是预期的防漏行为。旧档案不自动删除，也不自动将聚合先例拆成虚构记录；旧先例拆分和完整操作界面试作仍是后续独立工作。
