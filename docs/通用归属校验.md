# 通用归属校验（1.6.3 修复）

## 这次修正的共同路径

所有正文成果在字段规范化、状态栏/子表定位及来源解析之后进入同一个归属入口。批量整理、修复候选重新校验和直接规范化都使用这一入口。证据判断不创建档案ID，也不合并记录。

- 展示标题的其他词条前缀不再等于实际归属；真实引用、明确声明和已有独立身份继续参与校验。
- 结算和状态片段的所属标题对后续行生效。下一所属标题开始新的范围；普通地点如“尽有战界·灰雾旧街”不作为金手指名称。
- 引用跨越不同所属范围时保留待核对；模型填写当前ownerPowerId不能覆盖冲突。已有ID与原状态栏同样接受这项检查。
- 原状态栏依声明的单行/具名身份定位；子表依archiveId、分类和声明身份列定位。地点相同、标题相近不作为合并不同事件的依据。
- 新对象不能仅用分类名称充当具体对象；省略operation也不能绕过。单行主槽继续使用既有固定名称。

## 玩法规则与通用校验的边界

通常的明确叙事不强制逐字出现词条名。把这项要求扩到所有词条，会误拒绝大量有效剧情。模型仍需按任务中的规则判断机制联系；程序并不能完整理解所有自然语言。

有明确必要联系的玩法使用与规则哈希绑定的ownership声明，由共同算法核对连续引用、现有对象、明确事实锚点和声明机制。原有挂机限制迁入该声明，整理流程不再按挂机的adapterId或discoveries分类另写分支；声明中的机制必须实际出现在绑定原文里，模型自行填写ruleQuote不授予权限。原状态栏与已有对象不被当成首次建立独立对象。

太始天的世界ID、人物关系端点和显式纳入范围属于世界模型的业务限制，继续保留；漫漫长路的独立身份限制同样保留。这些约束不等于所有词条共用的标题判断。原规则、存储结构和玩家资源未迁移或重算。

## 审查与验证

审查覆盖archive-review、archive-ownership、archive-protocol、archive-tables、builtin-statusbar、taishi-ownership、归属相关修复入口及填表预设。原始规则声明与玩法表结构没有重写。

新增测试遍历所有普通内置词条的可写原状态栏，检查概括标题、正确分行来源、外部来源拒绝、未推进失败楼层；遍历默认实体表的分类标题拒绝。另测混合归属、地点名称、计划区排除、多个机制声明、已有ID不能绕过归属和跨词条原档保留。

测试使用合成材料；玩家失败候选仅本地回放，不进入仓库。自动测试不能证明实际模型永不误判，未作真实酒馆安装与付费模型调用。
