## 任务分工

| 模式 | 依据与职责 | 输出边界 |
| --- | --- | --- |
| 正文整理 | 正式结算优先，状态快照核对，叙事补充；完整检查本层适用事实 | changes、逐层报告、简短说明；不重新执行能力 |
| 玩家补充 | 仅整理玩家明确手写内容 | 愿望、尝试、已有成果按实际状态区分，来源-1 |
| 世界书底稿 | 仅读取所选书、词条及片段 | 保留原始设定细节和settingRefs，不当作新收益 |
| 建档草案 | 玩家明确的类别、构想与加入方式 | 可在许可范围补全草案，不冒充已发生事实 |
| 自主发展 | 已开启开关、指定世界、内部历时、现状与目标 | 仅指定范围内的发展候选，沿用重大后果限制 |
| 高级世界专职 | 世界、区域、组织、事件、文明、建设与已有成果 | 仅允许本职recordSchemas，报告仅统计本职输出 |
| 高级人物专职 | 人物与眷属设定、当前动态和认知边界 | 只处理companion，遵守玩家筛选和加入方式 |
| 高级摘要专职 | 汇总已生成候选及未解决问题 | 仅message，不生成档案或声称已保存 |

基础入口依旧单模型。多个提示组在一次请求内按顺序拼装，不意味着多次调用。高级入口仍使用既有世界、人物、摘要调度，不增加自动重试或额外思考调用。

## 输出与输入对齐

预设按职责、任务、背景、领域规则、任务边界、处理步骤、输出格式、条件输出、最终检查拼装；没有启用的条件组不发送。rules、聊天、已有档案等数据仍在user JSON中，系统提示只放维护的任务规则。

输出保留插件实际接受的changes格式，不改成外部引擎的JSON Patch。通用fields只使用fieldTypes[type]字段ID，专用details只使用recordSchemas对应字段ID。每个字段只写一次，未知省略，不同时写ID和中文标签制造冲突；合法通用档案可以保留无法可靠映射专用分类的事实。

先清点事实，再决定字段，不先按模板筛掉其他成果。正式结算里的本轮收益、状态变化、新增解锁逐项检查；后续机会不当作已执行成果。人物外貌、性格、经历、能力、战斗方式或日常技艺分别保留，不压成职责摘要。

每层的floorReviews与实际变化数量一致；无新增也明确报告，未完成用uncertain。guide的1至6个玩法方向限制只属于玩法说明，不限制成果数量。安排与拟定进展数组仅在相应任务启用时声明；同一对象同一层合并，多层变化按顺序保留历史。

系统不要求模型输出长篇思维过程。可观察的依据是候选、来源、逐层数量和未解决问题，而不是隐藏推理内容。复制提示中的检查步骤本身不能保证真实模型提取完整。
