# 长期子表第二批（1.6.1）

本轮在 1.6.0 基线上扩建第二批子表，并合入 DS 的界面改动，作为 1.6.1 更新。后端新增与界面改动分别核对后合并，原存储、确认流程和余额逻辑继续沿用。

## 范围

新增 7 个词条、24 类长期记录。20 类沿用原有分类与字段，补齐咨询法 3 类、万灵图鉴远行/重要敕令 1 类。与已发布首批合计 16 个词条、52 类。

| 词条 | 长期分类 | 主要边界 |
| --- | --- | --- |
| 生命球 | 待化身定义、生命库、跨形态熔铸、共同主体 | 识别不是已化身；切走不删除旧形态；同一特征按接收形态区分，源形态保留；共同成长不等于全库每种形态都升级 |
| 拓印 | 永久模式、状态复刻、关键调用与防御 | 印数不因释放消耗，也不是共享钱包；临时状态结束不删除蓝图与期间所得；融合保留原模式 |
| 万灵图鉴 | 正册、影页、生态、远行与重要敕令 | 影页转正沿用原身份和分类更新关系，不能复制成员；火种、温养、恢复与完整助力分别记；普通日常不逐条入表 |
| 模板 | 各层个人位格、征服模板、唯一当前配置、连续冲突 | 当前配置不等于永久库存；切换不晋升、不重置阶段恢复；同场冲突不因短暂脱战重算；倍率不写回基准 |
| 挂机 | 唯一影子、探索首通、战利与待回流、真实成长 | 重整还是同一影子；唯一实物按实际去向；双向同步不增殖成长；战界模板不冒用其他权柄的倍率与槽位 |
| 咨询法 | 对象与版本、已承接力量、已成组合 | 名称和具体版本共同定位；共鸣按对象保留，不设共享点数；切换不清空旧咨询；独立有效的普通练习也更新对应进展 |
| 每日情报 | 有后续价值的情报/追踪、唯一关注网络 | 每日十讯、锁定名额、危机插播分别理解；不要求每期全部常驻，不按电脑日期刷新，也不把机会当到账 |

上述分类是“允许长期保留的内容”，不是新增玩法、自动奖励或硬凑每轮记录的任务清单。仍以当前原文、真实已发生事实及玩家确认范围为准。

## 新增字段

- **远行与重要敕令**：实际成员与队伍、已授权目标、实际进展与阻碍、已得与待带回。
- **咨询对象与版本**：对象名称、来源与具体版本、主要特质承接、未兑现共鸣、咨询/固化状态、重要经历与兑现依据。
- **已承接力量**：对象与版本来源、实际可用内容、真实深化、作用与边界。
- **已成传说组合**：已有组成与来源、实际组合效果、当前掌握与发展、作用条件。

未明确的字段留空。插件不会按三次共鸣自动发奖或扣除积累，不把数字变化当作实际能力；只登记正文确认的真实兑现和剩余进展。日常实践若确实独立有效，更新原咨询行即可，不另建每次训练的流水。

## 身份和跨分类约束

`identityFields` 声明明确的身份列。当前用于咨询法的对象与版本：新建 insert 需要完整填写；同一对象与版本即使换显示标题，也定位回原行。AI 不得把已有行的版本改成另一版本；真实不同版本用明确不同的名称分别保存。需要更正原身份时由玩家手动核对，避免自动覆盖。

`exclusiveWith` 声明同一生命在影页/正册之间不能复制身份。已有影页正式加入后继续使用原 archiveId 和 recordId 更新关系，旧分类保留，不自动迁移；同批同时复制影页和成员会阻止后一个候选。已存在的历史重复不自动删除或合并。不同个体只是名称相似时不会模糊合并，仍需玩家核对。

唯一征伐之影、当前模板搭载、生命球共同主体及每日情报关注网络使用单行现状；重复新建被拒绝，正常更新沿用旧行。旧合法缓存候选继续兼容，身份列要求主要作用于新请求明确声明的 insert 操作，不倒推初始化历史字段。

## 数据与 UI 合并边界

继续使用 ChatStore、archiveId、既有子表协议和候选确认。没有新存储或 SQL 服务；没有自动迁移、删档、扣款或资源结算。原文指纹变化后不套用旧适配。

子表开发阶段保持 UI 不变；接入 DS 成果时只修改经对比的 `src/ui.js`、`style.css` 及对应说明，版本同步为 1.6.1。现有 UI 从相同 `archiveTables` / `creationConfig` 接口读取新增分类；保留 data-action、表单 name 和事件绑定，无需手工重写 52 套表单。

合并 DS 成果时只取经核对的 UI 文件差异，不能把它持有的整份旧源码反向覆盖到当前工作目录。逐个比较它基于 1.6.0 改过的文件；若涉及子表声明、保存、身份或规则文件，先评估实际冲突再合入。验证材料保留在源码外的本地开发目录，不随项目提交。

静态与模拟宿主验证不等于真实酒馆、多插件组合、真实模型或玩家验收。
