# 更新处理与手动合并

适用版本：1.6.9。

## 更新结果

确认窗口分别显示主状态栏、子表新增与更新、其他档案、内容无变化、待处理项和跳过项。无变化只统计确实返回且与现有内容一致的候选。没有返回内容的子表显示“未返回可核对内容”，不能据此判断剧情未提及或模型漏填。最近一次整理按实际保存记录汇总，不把待确认候选当成已保存。

## 失败后继续处理

普通词条和漫漫长路部分保存后，保留失败及未勾选的候选，更新缓存的聊天版本；已完整保存的候选移出本轮。保留下来的拟定进展重新关联剩余候选或已保存档案的编号，避免列表序号变化导致串档。太始天继续使用已有分阶段续跑与世界书批次恢复流程。

错误浮层可直接打开当前词条剩余候选；接口或发送前检查失败可进入连接设置，保存失败可重试保存。具体条目提示该选择目标、处理字段冲突还是修正字段。AI 修复入口仍需玩家点击并标注消耗 API；没有增加后台模型请求。

## 手动合并

普通词条的“更多操作 → 合并重复档案”可以选择两份记录；同名子表提示也能直接进入。不同名称也可手动选择，同名不会自动合并。

流程：选择保留记录和并入记录 → 查看两份内容与来源 → 逐个选择冲突字段 → 查看最终保留内容 → 确认保存。全过程不调用 AI。空白字段补入另一份已有内容，数量不相加，保留历史和来源，沿用原有撤销入口。不同类型、模块或专用分类不强行合并；记录或正文改变后需重新预览。

验证使用自编资料和模拟宿主，不包含真实模型或玩家聊天写入。真实酒馆现场操作仍待验证。

## 常用入口与预览

当前词条旁的“管理词条”集中提供规则、暂停/恢复和删除。删除继续二次确认并可先导出备份。顶部“待处理”只列当前聊天仍有效的整理候选、角色同步与已呈现行动；点击整理结果会进入对应词条，不会自动接受。查看待处理不会清除红点。

逐字段差异之后可展开“保存后完整内容”，其中包含未修改但保留的字段。撤销预览直接列出恢复的原内容，确认后才恢复。

## 输入范围与调用量

活动提示展示本次请求读取的正文楼层、参考前文条数、档案详情与身份目录数量。前文仍只用于参考，有长度上限时标明含节选。正文仍完整读取；超长单层可使用原有分批入口。

本轮累计统计实际发出的模型请求与插件文本输入字符，包含多阶段与重试；本轮结束后新任务从零开始。它不含酒馆额外注入，也不是实际计费或平台账单。

大档案仍保留全部对象身份目录，详情优先级为主状态栏、本轮明确提到的名称/编号/曾用名、再到关联对象；不截断单个字段，不删除玩家数据。若目录与规则本身过长，继续使用现有发送前提示，不静默丢弃事实。
