# 剩余词条子表审查与分批制作

审查基线：本地1.6.2，主词条115个；此前已审32个，38类默认子表、69类旧分类兼容。此次逐项审查其余83个，不按原适配器字段数量直接拆表。

## 判断标准

只有需要跨回合保留、以后仍可独立调用且自身有变化的重要对象才建表。当前整体状态由原状态栏维护；临时过程、普通奖励、每次消耗、练习和生产批次不建流水。表少不代表丢弃事实，重要成果仍由原栏或既有档案保存。

这次选择18个词条、21类默认表，分6批，每批3个词条。64个本轮不追加；太始天已有专用结构，单列排除重复建设。之前已撤回默认表的等价交换、我全都要、多倍收获系统继续不新增。漫漫长路已有专用表格模式，不属于这83个，也不重复制作。

排除是按当前证据作出的扩表取舍，不关闭既有适配器或删除旧档，也不宣称它们以后永远不需要子表。本我完满宝诰、灼魂之焰没有此处可识别的原状态栏，不为排除而虚构已有面板。

## 每批写入边界

### 第8批 · 至高亡灵主宰

- 只保留需要独立接续的重要成员或真实具名编制；普通军势规模、永久本源增长、当前可用军势、领域与役事仍由原状态栏总览承接，不扩建贡献和每次复起流水。
- 创造新亡灵与复起特定死者分清：前者无须尸骸，后者按真实对象联系；不能因缺尸骸削弱创造，也不能凭名字捏造已复起的旧人。
- 同一成员复起、重构、跨界部署和能力深化沿原ID；原身份、重要经历和真实战损保留，不按出场次数增加军势，不把永久本源与即时可用兵力混为一笔。

收拢去向：feedback → 原状态栏/既有库存；旧档继续兼容；domains → 原状态栏/既有库存；旧档继续兼容；undertakings → 原状态栏/既有库存；旧档继续兼容

### 第8批 · 攻略系统

- 人物是唯一长期主体，阈值领取记录和明确来自该人物的实际奖励附原人物详情；共享奖励、无明确人物归属的物品及商店按原状态栏或已有库存承接，不强行复制到多人。
- 每个人独立维护当前好感、阶段与已领取阈值；降低当前好感不回收既得成果，重新达到旧阈值不重复领取，新阈值以正文实际发生为准。
- 原文指定关系与实际旧经历据实保留，不凭规则样例初始化所有人物；不根据阈值自动发奖、补算点数、购买或建立第二份积分账本。

收拢去向：thresholds → 重要关系人物详情，仅明确所属时；rewards → 重要关系人物详情，仅明确所属时；points → 原状态栏/既有库存；旧档继续兼容；shop → 原状态栏/既有库存；旧档继续兼容

### 第8批 · 奇迹智子

- 只保留真正需要独立接续的重要集群或关键个体，普通子体和日常产量归原总览，不逐个造册；同一批成员不同时登记为多个可用集群。
