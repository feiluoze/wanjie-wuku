# 太始天填表与可靠更新 · 1.6.5

太始天的表格、概况与详情共用现有档案。进入人物、文明、发展事项等分类后默认显示表格，也可切换卡片。表格显示重点栏目，行末“查看详情 / 修改”可查看完整字段和来源；手机使用堆叠行。

## 如何整理

先确定所属世界和对象，再提交实际变化的栏目。已有对象沿用原 ID，改名、迁移和阶段变化不另建副本。不同已登记世界的同名对象可以分别保存；缺少世界或存在多个同名候选时必须明确 ID，程序不猜测合并。普通人物不自动成为眷属。

世界、区域、势力、族群与文明维护现状；发展事项追踪重要建设和研究；可调用成果维护实际可用内容；事件及界主所得保存独立历史与反哺。普通活动、每轮情绪和重复使用能力不成为新事件。

## 旧楼层、冲突和遗漏

- 当前状态：模型标注过期栏目后，程序按该字段实际变化的历史检查较新正文来源，证明成立才自动跳过。只凭整条记录的最后楼层、数字更大或电脑时间不成立。
- 独立历史：事件和界主反哺不允许作为旧快照丢弃。人物能力、设定、认知和长期记忆也不进入可自动丢弃的栏目。
- 独立遗漏：旧层漏记的重要成果仍能补录。某字段冲突时，其余有依据的内容继续核对。
- 真正冲突：来源不明、已改写分支、玩家保护字段和无法拆开的矛盾继续待查，不自动选最新或最大值。

`fillPolicy.tables` 提供本次分类、记录用途及允许过期处理的 `snapshotFields`。`current.fieldSourceIndexes` 提供可推导的栏目最后实际变化来源；缺项表示无法证明。已有 `staleFields`、`uncertainFields` 及逐层报告共用基础归档校验，不绕过世界归属或保存检查。

## 不同任务的边界

| 任务 | 依据与权限 |
| --- | --- |
| 正文整理 | 只提取所选正文事实，按玩家自动保存设置处理 |
| 世界书初始化 | 只读明确所选片段，保留原文引用；底稿不覆盖已有剧情现状 |
| 玩家补充 | 只采用明确补充，不扩大为其他对象收益 |
| 建档草案 | 指定对象内生成候选，确认后采用 |
| 自主发展 | 仅所选世界、内部历时和人物范围；确认后推进，不自动缔约或授权重大后果 |

底稿、草案和自主发展不以文件顺序、电脑时间或生成时间使正文过期。程序历时、改设资格、人物身份及玩家锁定的关系继续由原入口管理。

## 高级工作流与失败处理

生产入口先核对世界，再更新人物，最后生成显示摘要。人物可以参考尚未保存的世界候选，但不能编造它们的正式 ID。世界及人物分别核对本角色的来源、字段和逐层数量，失败原因会合并到预览。普通与高级最终通过同一保存队列。

摘要不修改候选。摘要失败时显示基础摘要，有效事实可直接保存；保存之前仍可单独续跑摘要。事实阶段失败保留其他成功阶段，只续跑所选失败阶段。

自动更新仅对临时传输错误有限重试。实际接口尝试、备用接口和手动阶段续跑合计每阶段最多 3 次，三个阶段累计最多 9 次；取消的请求也消耗已发出的次数。鉴权、余额、字段冲突和 JSON 语义错误不盲目重抽；酒馆当前生成超时不会在同一连接重复启动。关闭或切聊天会取消后续请求，迟到回复不能写入新状态。

账户预设按基础整理、世界、人物、摘要等任务各自配置，导入不修改太始天档案。预设不能绕过来源、身份或格式校验，也不保证模型一定正确或不拒答。

本版本不新增外部数据库、不批量重写旧档或历史。存储写入、浏览器显示、真实模型效果及真实宿主安装是独立验证边界。
