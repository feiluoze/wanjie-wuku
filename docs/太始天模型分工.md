# 太始天模型分工

在太始天首页点“模型分工”，选择单模型、分工协作或深度推演。旧档未开启高级核对时仍使用单模型；此前开启高级核对的聊天继续分工，但默认改用程序摘要，少一次固定请求。

## 三种处理方式

| 方式 | 处理流程 | 通常请求数 |
| --- | --- | --- |
| 单模型 | 沿用普通整理与原连接设置 | 1 |
| 分工协作 | 世界与人物分别核对，程序合并 | 1—2 |
| 深度推演 | 分工后增加因果复核，只提出问题与建议 | 2—3 |

额外 AI 世界简报由玩家勾选，通常增加一次请求。自主发展先世界、后人物；人物造成世界后续影响时，最多增加一轮世界协调。世界协调和世界首次请求共用同一个岗位预算，不重新计算历时。上表是没有失败与重试时的通常数量，不是费用承诺。

范围、额外简报和岗位请求上限用于分工与深度推演。单模型继续使用普通整理设置。自动范围只按可用类别和玩家选择排除无关岗位，不凭陌生姓名猜测有没有人物；不确定时两边都核对。人物筛选为空仍可能需要整理组织之间的关系。主动选择“仅世界”或“仅人物”时，可保存对应候选，但不标记整层剧情已全部核对。

## 连接与模型

点“配置岗位连接与模型”，在连接设置的任务分流中，为世界、人物、因果复核、世界简报分别选保存过的连接方案。留空沿用当前连接，岗位也可以使用同一个模型。Key 保留在账户连接设置，不写进聊天档案或任务提示。

酒馆直连共用酒馆当前连接与模型，按先后执行，不临时改酒馆全局模型。需要不同模型时，为岗位选择独立 API 连接方案。所有参与连接均为独立 API 的剧情核对可以并行；自主发展始终先世界、后人物。

世界岗位负责世界、文明、区域、组织、事件、建设发展、可用成果、个人反哺和降界记录。人物岗位负责人物与关系。岗位可以提出跨岗位影响，但不能直接覆盖另一岗位的表。

## 预览与采用

剧情核对只能记录正文事实。自主发展生成的内容属于指定世界、指定历时的待确认创作，不冒充正文事实；世界秘密不会因为传给人物岗位就自动变成人物已知信息。

新对象可以在候选里互相关联。程序使用临时引用组织预览，确认时先保存被依赖对象，再写入真实档案编号。关联目标未通过校验时，依赖项暂缓；其他独立候选仍可保存。不能只接受依赖者而取消它依赖的新对象。

深度推演发现具体矛盾时，相关候选暂缓保存，列出原因与建议。玩家可核对后选择“保留原候选”，该选择在本地执行，不再调用模型；也可保留待处理或放弃剩余候选。复核模型没有写档权限，也不能直接修掉原文事实。可选复核或简报请求失败会提示，原有有效候选保留。

## 失败与恢复

- 默认每岗位实际接口尝试最多 3 次，可改为 1 或 2 次。首次请求、网络重试、格式修正、预选备用连接和世界协调共同计数。
- 格式错误最多自动修正一次；已经得到的有效候选保留。临时网络错误沿用自动更新的有限重试；手动续跑只处理点击的岗位，不暗中继续后续付费阶段。
- 备用连接只使用玩家提前选择的方案。不会因失败自行挑选更贵模型。
- 成功岗位和剩余候选缓存在本机；部分保存后移出已保存项，再续跑失败岗位。刷新能否恢复取决于浏览器缓存是否可用及内容是否仍与当前聊天匹配。
- 聊天分支、原文、相关档案或分工设置改变后，需要重新核对。只有本轮确认的部分保存能在检查原始来源不变后接续。
- 手动自主发展先保存世界历时再续跑人物时，同一批历时只采用一次。来自正文历时或时间调度的事件仍整批确认，防止同一时间段重复采用。
- 关闭任务窗口只收起界面；明确取消才停止请求。远端是否已经停止计算取决于接口。

## 开发验证边界

自动化检查使用本地模拟酒馆和假模型响应，覆盖分工、失败续跑、临时引用、部分保存、因果复核、重复候选、预算与手机布局。它们不能证明某个真实模型的质量，也不代表已经安装到玩家酒馆或完成真实 API 验收。
