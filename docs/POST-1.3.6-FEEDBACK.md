# 1.3.6发布后反馈：通用候选误拦截

状态：源码已修改，尚未重新打包、安装或发布。

日志确认1.3.6最近的失败请求包含多层正文，接口正常返回；默认日志不含候选全文，不能证明全部历史事实是否提取。截图中的语言候选被“已有专用分类必须提供recordId”拦截。这是过度约束，不是缺失读取权限。

本轮修正：

- 删除“只要适配器有专用分类就拒绝通用候选”的统一限制。已有合法通用类型、字段、来源和归属仍可保存；专用分类优先，不猜测分类，也不删除专用校验。
- 明确给出recordId/details时继续校验；错误ID和未知字段仍拒绝。已有专用对象继续保留其专用数据。
- 候选来源可唯一定位时，失败仅阻塞该层；无法定位才保守保留全部相关层待重查。
- 前端逐层状态与实际blockedFloors一致，存在拒绝候选的层不能再显示完成核对。

验证：922项离线回归，909通过、0失败、13外部样本跳过。补充有效通用候选、无效专用ID、明确来源的单层失败以及来源不明的保守处理。没有调用真实模型或改动玩家档案。

尚待处理：通用与专用重复字段的真正冲突展示及现场修正；长历史逐层提取完整率及分批策略。不能把模型自报“零项”视为已经证明该层没有任何成果。本次修正解决错误拦截，不宣称模型已能提取全部历史成果。

本轮修改不在原1.3.6ZIP中，发布下一包时需同步更新版本和验证说明。

上述修复已纳入1.3.7源码与本轮安装包；验证与限制以RELEASE-1.3.7.md为准。
